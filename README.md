# 고프코어 패션 페어 서울 2027 (GORPCORE FASHION FAIR SEOUL)

전시산업론 중간고사 개인 과제. 교수님 템플릿(6장)의 레이아웃·글꼴(Noto Sans KR)·색을 그대로 따르고, 안내 문구 자리를 실제 기획 내용으로 채웠다.

- 제출용 원본: `GFF_SEOUL_2027_전시산업론_중간과제.pptx` (본문 6장 + 별첨 2장 「전화 검증 기록」)
- 확인용 미리보기: `GFF_SEOUL_2027_미리보기.pdf` (LibreOffice로 변환한 파일이라 한글과 영문·숫자 사이 간격이 PowerPoint보다 넓게 보인다. **제출용 PDF는 PowerPoint에서 직접 내보낸다.**)
- 각 슬라이드 **발표자 노트**에 설명 대본이 들어 있다.

## 기획 배경의 논리 (1장)

현상 → 문제 → 역설 → 원인 → 실마리 → 기회 순서로, 앞 단계가 다음 단계의 근거가 되게 쌓았다.

1. **현상** — 국내 아웃도어 시장은 약 7조(2014) → 약 4조(2024)로 줄었지만 아크테릭스는 2024년 41% 성장. 무신사 프리미엄 아웃도어 아우터 거래액은 2026년 가을 2배. 수요가 '등산복'에서 '고프코어 패션'으로 옮겨갔다.
2. **문제** — 2024년 상위 12개 브랜드 중 성장한 3곳(노스페이스·스노우피크어패럴·아크테릭스)은 모두 해외 라이선스·직진출. 국내 오리지널 4곳은 모두 역성장, 노스페이스 로열티는 151억(2020) → 337억(2023).
3. **역설** — 영원무역은 40여 개 글로벌 브랜드를 생산하고, 코오롱의 투습방수 원단은 노스페이스·컬럼비아에 수출된다.
4. **원인(병목 세 곳)** — ① 소재·제조 ↔ 브랜드 단절(최소주문량·심실링·PFAS 전환) ② 고비용 국내 유통(무신사 평균 수수료 27.8%, 백화점 최고 38%, 특약매입 59.9%) ③ 해외 접점 부재(기존 장치는 플랫폼 전속 또는 디자이너 의류 중심).
5. **실마리** — 코오롱스포츠는 중국 안타와 손잡고 5년 만에 26배 성장(매출 1조). 무신사 도쿄 쇼룸에 일본 바이어 200명 이상, 무신사 스탠다드 첫 서울 수주회(2026.8)에 조조타운·티몰·동남아 바이어.
6. **기회** — 소재·제조·K-브랜드·국내외 바이어를 한 자리에서 잇는 고프코어 거래의 장은 아직 없다(정부 'All in Korea' 230억 사업도 2026년 시작 단계).

| 장 | 내용 |
|---|---|
| 1 | 전시회명·작성자·고프코어 정의, 기획 배경 사다리, 기존 전시회 5곳과의 차이 |

| 3 | 목표 3개 × (달성할 내용 / 확인할 지표·방법 / 설정 근거 = 비교 근거 + 산식 + '우리 행사라서 가능한 이유') |

### 수업 내용과의 연결
- 교수님 강의의 "한국은 패션 코어 국가인데 패션 엑스포가 없다", "해외 플랫폼이 한국 브랜드를 사고 싶어 한다" → 기획 배경의 출발점.
- "큰 문제, 산업 구조 차원의 문제여야 전시회를 열 이유가 생긴다" → 몇몇 브랜드의 불편이 아니라 산업 전체의 가치 유출 구조로 문제를 정의.
- "참가업체는 카테고리별로, 바이어는 실제 기업명으로, 네 칸 표로" → 5장 E1~E6 / B1~B7 / 연결표.
- "이해관계자에게 이익을 줘야 동조한다" → 6장 이익 칸을 각 기관의 실제 사업 목표(All in Korea, 수출 실적, MICE 실적 등)와 연결.

## 교수님 제출 기준 (녹취 기준)

- 제출 마감 **11월 3일**. PPT 양식(스마트리드)에 작성한 뒤 **PDF로 변환해 업로드**. 파일명은 **본인 이름과 학번만** (예: `홍길동_20261234.pdf`).
- 별첨(전화 검증)은 **최대 2장** → 별첨 1/2(참가업체 측), 2/2(바이어 측)로 맞춤.
- 전화 검증은 **참가업체 1곳 + 바이어 1곳 이상, 총 2곳 이상 필수**(다다익선). 이름·소속·전화번호·통화 일시, 핵심 발언(불릿 또는 녹취 원문), 사전 가정, 통화 후 추가 확인 사항을 적는다.
- 11월 3일 수업에서 무작위로 팀을 짜고 각자 기획안을 공유해 팀당 1개 행사를 고른다. 날짜·장소·예산은 그다음 단계.

## 제출 전 해야 할 일

- [ ] 모든 슬라이드 우측 상단과 1장의 `( 이름 / 학번 )`을 본인 정보로 교체. 우측 상단 표기는 슬라이드 마스터에 있어서 **보기 → 슬라이드 마스터**에서 한 번만 고치면 전체에 반영된다. 1장 '작성자' 칸은 직접 수정.
- [ ] 별첨 1/2의 전화번호 칸 기입(개인정보이므로 저장소에는 넣지 않음).
- [ ] **바이어 측 통화 진행(필수)** — 별첨 2/2의 질문지로 통화하고 시도 기록표를 채운 뒤, 6장 '바이어 측 · 진행 예정'을 '완료'로 바꾼다. 연결 실패도 시도 내역으로 남긴다. 공급 측 2곳(벤텍스·기도산업)은 선택이지만, 소재관·제조관 수요를 직접 확인하면 근거가 훨씬 단단해진다.
- [ ] 참가업체 측 인터뷰는 녹취록 기준 **대면** 인터뷰로 기록했다. 과제 양식이 '전화' 검증이므로, 필요하면 같은 분께 짧게 전화로 별첨 1의 '통화 후 추가로 확인할 사항'을 묻고 방식을 함께 적는다.
- [ ] 핵심 수치 원문 확인(아래 출처). 이 작업 환경에서는 기사 원문 페이지에 직접 접속할 수 없어, 검색 결과에 인용된 원문 문장으로 교차 확인했다.
- [ ] 글꼴: 템플릿과 같은 Noto Sans KR을 쓴다. PC에 없으면 PowerPoint가 다른 글꼴로 대체하니 설치 후 줄바꿈을 한 번 확인.
- [ ] PowerPoint에서 **파일 → 내보내기 → PDF**로 저장하고 파일명을 `이름_학번.pdf`로 바꿔 업로드.

## 작성 원칙

- **줄바꿈은 의미가 끝나는 곳에서만.** 모든 문장을 의미 단위·문장 단위로 미리 끊어 두고, 빌드 스크립트(`build/lib.js`)가 각 줄의 실제 폭을 Noto Sans KR 글꼴 지표로 재서 상자를 넘으면 빌드를 멈춘다. LibreOffice가 한글과 영문·숫자 사이에 넣는 자동 간격(0.234em, 실측 보정)까지 더해 검사하므로, PowerPoint와 LibreOffice 어디서 열어도 문장 중간에서 끊기지 않는다.
- **로고 대신 이름 배지.** 이 작업 환경은 외부 사이트 접속이 막혀 로고 이미지를 받을 수 없었다. 대신 모든 회사·기관을 같은 모양의 이름 배지로 통일하고, 국내 기업 / 해외 기업 / 해외 IP 라이선스를 색으로 구분했다.
- **확인된 사실만.** 회사·기관명과 수치는 출처가 있는 것만 넣었다. 가정한 숫자(샘플 의뢰 전환율 1/3 등)는 슬라이드에 '가정'이라고 밝히고, 1회 실측 후 고친다고 적었다.

## 수정 내역

**3차 (분석 깊이 보강 — '가치 유출 구조'로 재구성)**
- 1장: 고프코어 정의 추가, 기획 배경을 현상 → 문제 → 역설 → 원인(병목 3곳) → 실마리 → 기회의 근거 사다리로 다시 씀.
- 2장: 미션을 소재·제조사 / K-브랜드 / 바이어 세 이해관계자의 문제로, 비전에 '행사의 모양새'와 산업 변화 3가지를 담고, 배경과의 연결을 서술 + 병목별 표로 정리.
- 3장: 목표를 150개사 / 800만 달러 / 사전 매칭 300건으로 바꾸고, 산식과 '우리 행사라서 가능한 이유'를 근거로 붙임.
- 4장: 밸류체인을 7단계 한 장 지도로 다시 그림(실제 기업 배지, 돈의 흐름, 지원 기능, 병목 위치, 전시 범위와 선정 이유).
- 5장: 참가업체 6그룹(소재관·제조관 정식 포함), 바이어 7유형, 구매 이유에 병목 번호를 단 연결표.
- 6장: 이해관계자 12곳, 이익 칸을 각 기관의 실제 사업 목표와 연결.
- 별첨: 기획 수정마다 근거 질문 번호를 달고, 새 기획에 맞춘 추가 확인 사항, 바이어·공급 측 가정 H5~H8, '가정이 틀리면 바꿀 것' 추가.
- 줄바꿈 검사기 도입(의미 단위 줄바꿈 보장), 파일 압축 적용.

**2차 (추가 녹취 반영)** — 교수님이 슬라이드별 작성 기준을 설명한 녹취에 맞춰 수정(산업 구조 차원의 문제 정의, 날짜·장소 가안 표시, 비전의 산업 변화, 물류·마케팅 서비스 추가, 녹취 원문 인용).

## 다시 만들기

```bash
cd build
npm install
npm run build   # ../GFF_SEOUL_2027_전시산업론_중간과제.pptx 생성
```

- 슬라이드 1~3장은 `build/build_deck.js`, 4장은 `build/slide4.js`, 5~6장은 `build/slides56.js`, 별첨은 `build/appendix.js`에 있다. 공통 도구(줄 폭 검사, 배지, 표)는 `build/lib.js`.
- 문장이 상자 폭을 넘으면 빌드가 '폭 초과' 오류와 함께 멈춘다. 그 줄을 의미가 끝나는 지점에서 다시 끊으면 된다.
- 글꼴 지표는 npm 패키지 `@expo-google-fonts/noto-sans-kr`의 TTF를 쓴다(`FONT_DIR` 환경변수로 바꿀 수 있음). PowerPoint에서 직접 고쳐도 된다.
